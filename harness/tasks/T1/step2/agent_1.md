# A1-Architect Cross-Critique -- T1

## Critique of Other Agents

### On A2-Pragmatist

- **Agree**: No tsx dependency at T1. A2 makes a strong case that vitest handles TS natively for tests, and `tsc && node dist/index.js` covers manual runs. I included tsx in Step 1 for developer ergonomics, but A2 is right that the primary feedback loop is tests, not manual CLI invocation. tsx can be added when someone actually needs it (likely T7 when the CLI is wired up). I am revising my position on this.

- **Agree**: No pre-created subdirectories (`src/lexer/`, `src/parser/`, etc.). A2 argues "the task that needs the directory creates it." This is correct -- empty directories are noise in git (they are not even tracked without a placeholder file). My Step 1 proposal showed the full directory tree as a design artifact but did not explicitly say to create empty directories at T1; however, it was ambiguous. A2 makes the right call: only `src/`, `tests/`, `examples/` need to exist at T1.

- **Agree**: No coverage config at T1. Coverage is a measurement tool, not a scaffolding concern. Add it when there is code to measure (T2+).

- **Disagree**: `declaration: false` and `sourceMap: false`. A2 argues these are unnecessary at T1 scale. While technically true, these are zero-cost defaults that prevent a "forgot to enable" problem later. `declaration: true` costs nothing (generates .d.ts files nobody reads yet) and `sourceMap: true` costs nothing (generates .map files). Turning them off to "save" nothing and then needing to remember to turn them back on is a net negative. The pragmatic choice is actually to leave them on -- less future work, zero present cost.

- **Disagree**: `src/index.ts` as just `console.log('graft')` without Commander setup. A2 defers Commander to T7, but the implementation plan explicitly lists Commander as a T1 dependency. Setting up the minimal CLI skeleton (two commands: `compile` and `check`) with TODO bodies takes 20 lines and validates that the Commander dependency actually works. A placeholder `console.log` validates nothing about the dependency. If we are including Commander in `dependencies`, we should prove it works.

- **Disagree**: No `check` script. `tsc --noEmit` is not redundant with `tsc` -- it serves a different purpose. `tsc` builds (slow, writes files). `tsc --noEmit` type-checks only (faster, no side effects). During development, you want fast type-checking without rebuilding. The `check` script is one line of config that provides genuine value.

### On A3-Skeptic

- **Agree**: The ts-node issue is HIGH severity. A3 correctly identifies that `node --loader ts-node/esm` is deprecated and broken on Node 22+. All four agents converge on this: use tsx or nothing, not ts-node.

- **Agree**: Missing `.gitignore` is a real issue. A3 correctly adds `*.tsbuildinfo` to the gitignore, which I overlooked. This file is generated by incremental builds and should never be committed.

- **Agree**: Shebang must be present from T1. A3's analysis of the cross-platform shebang behavior is thorough and correct. On Unix, missing shebang means `npx graft` fails silently. On Windows, npm generates .cmd wrappers that bypass it. Better to have it from day one.

- **Agree**: `forceConsistentCasingInFileNames` is essential on Windows. A3 correctly identifies this as a "ticking time bomb" -- code that works on Windows but breaks on Linux CI. Must be present from T1.

- **Agree**: `skipLibCheck: true` should be present. Without it, type errors in `node_modules` can block compilation. This is a standard defensive setting.

- **Partially Disagree**: `prepare` script. A3 recommends `"prepare": "npm run build"` to ensure `npm link` works. This is reasonable but premature for T1. Nobody is running `npm link` at the scaffolding stage. The `prepare` hook also runs on every `npm install`, which slows down dependency installation during development. I would defer this to T7 when the CLI is actually functional and someone might want to link it.

- **Agree**: Windows CRLF line endings in shebang is a real issue. A3 identifies that `#!/usr/bin/env node\r` will fail on Unix. However, this is a `.gitattributes` concern (set `*.ts text eol=lf`) or an editor setting, not a tsconfig concern. Worth noting but the fix belongs in `.gitattributes` or `.editorconfig`, not in the TypeScript configuration.

- **Partially Disagree**: `resolveJsonModule: true`. A3 argues it should be set up "correctly from the start" in case a future task needs JSON imports. This is speculative -- YAGNI applies. If T7 needs to import `package.json` for the version string, it can add this flag then. The cost of adding it now is near-zero, but the principle matters: don't configure things you don't use.

## Revised Approach

After reviewing all agents, I am revising my Step 1 proposal as follows:

### Changes from Step 1

1. **Drop tsx from T1 devDependencies**. A2 convinced me that vitest handles TS natively for tests, and manual CLI runs can use `tsc && node dist/index.js`. tsx can be added at T7 when the CLI is functional. This removes one dependency.

2. **Do not pre-create pipeline subdirectories**. Only `src/`, `tests/`, and `examples/` are created at T1. `src/lexer/`, `src/parser/`, etc. are created by T2-T6.

3. **Add `.gitignore` with `*.tsbuildinfo`**. Adopted from A3.

4. **Keep `declaration: true` and `sourceMap: true`**. Contrary to A2, these are zero-cost defaults that prevent future forgetfulness.

5. **Keep Commander setup in `src/index.ts`**. Unlike A2's bare `console.log`, the minimal Commander skeleton validates the dependency works and provides the CLI structure for T7 to build on.

6. **Keep `resolveJsonModule: true`**. While technically YAGNI, the cost is zero and it prevents a common future stumble. I am swayed by A3's argument here despite my initial instinct.

7. **Add comment to `hello.gft`**. Adopted from A4 -- exercises comment parsing, costs nothing.

8. **Drop `prepare` script**. Premature at T1. Add at T7.

9. **Drop coverage config from vitest**. Adopted from A2 -- add when there is code to measure.
