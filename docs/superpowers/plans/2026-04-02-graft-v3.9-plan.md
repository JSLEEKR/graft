## Rounds

### R1: Edge Transforms on Conditional Edges (MEDIUM)

**Justification for MEDIUM**: Design ambiguity — where in the conditional chain execution path to apply transforms (before branch evaluation? after? per-hop?). How transforms interact with multi-hop chains (apply at each hop? only first? only last?). How transforms interact with retry/fallback strategies on conditional edges. The runtime currently bypasses transforms entirely for conditional edges, so this is new behavior, not a fix. R-PROC-14 applied: wait for A2+A3 analysis completion before convergence.

**Apply R-PROC-14**: Wait for A2+A3 analysis completion before convergence.
**Apply R-PROC-18**: Convergence spec must explicitly list error path tests (transform on conditional edge to `done`, transform on conditional edge in cycle, transform with empty/null output).

**Scope**:
- Modify `executeConditionalChain` (or the caller in flow-runner.ts) to apply edge transforms when following conditional edges
- The existing `applyTransforms` pure functions (select, filter, drop, compact, truncate) are reusable
- Determine transform application point: per-hop vs end-of-chain
- Remove `SCOPE_TRANSFORM_CONDITIONAL` warning from scope checker (transforms are now supported)
- Remove `SCOPE_TRANSFORM_CONDITIONAL` from `ScopeErrorCode` sub-union
- Update scope checker tests that assert the warning is emitted

**Test target**: ~8 new tests (single-hop conditional with select transform, multi-hop chain with transforms, transform with `done` target, transform with filter on conditional, backward compat for edges without transforms, verify SCOPE_TRANSFORM_CONDITIONAL warning no longer emitted, transform interaction with fallback alias, transform on else branch)

### R2: Estimator Polish + TD-01 (DIRECT)

**Justification for DIRECT**: Three small, spec-constrained changes with no design ambiguity. (1) Diagnostic code specialization: mechanical -- add 2 codes, update 2 call sites. (2) Fallback cost: formula change with clear before/after (additive). (3) TD-01: replace regex with AST-based offset check using existing ProgramIndex data. R-PROC-12 applied: 3 small items merged into one round.

**Scope**:
- Add `BUDGET_CHAIN_CYCLE` and `BUDGET_CHAIN_DEPTH` to `BudgetErrorCode` sub-union
- Update `getConditionalBranchCosts` cycle detection to use `BUDGET_CHAIN_CYCLE`
- Update `getConditionalBranchCosts` depth limit to use `BUDGET_CHAIN_DEPTH`
- Update worst-case estimation for `retry_then_fallback`: `cost * (1 + maxRetries) + fallbackNodeCost`
- TD-01: Replace regex `from\s+"([^"]*)"` in `collectRenameLocations` with AST-based import path range check using ProgramIndex import declarations and SourceLocation offsets
- All 864 existing tests must continue passing

**Test target**: ~6 new tests (cycle warning uses BUDGET_CHAIN_CYCLE code, depth warning uses BUDGET_CHAIN_DEPTH code, BUDGET_EXCEEDED still used for actual budget exceeded, fallback cost included in worst-case for retry_then_fallback, TD-01: rename/reference skips identifier inside import path, TD-01: rename/reference still finds identifier outside import path)

### R3: Integration + Regression Tests (TEST-ONLY)

**Test target**: ~8-10 new tests
