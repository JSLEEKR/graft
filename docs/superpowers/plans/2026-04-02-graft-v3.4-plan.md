## Rounds

### R1: LSP Rename Support (MEDIUM — A2+A3 debate)

**Justification for MEDIUM**: Cross-file rename has genuine design ambiguity — how to discover all reference sites across files, how to handle imports that use the renamed name, workspace edit semantics. This passes R-PROC-13's "multiple viable approaches" test.

**Scope**:
- `textDocument/rename` handler in server.ts
- `textDocument/prepareRename` handler in server.ts
- `collectReferences()` function — gather all locations where a name appears in a program
- Cross-file reference collection using workspace export cache
- WorkspaceEdit construction with changes across multiple files

**Files touched**:
- `src/lsp/server.ts` — renameProvider capability, handlers
- `src/lsp/features/` — new reference collection function (after split in R2)
  - Note: R1 runs before the split, so references go in features.ts initially

**Test target**: ~16 new tests
**Agent calls**: ~4

### R2: Conditional Edge Estimation + features.ts Split (DIRECT)

**Justification for DIRECT**: Both changes are spec-constrained. Estimator fix is ~20 lines with clear semantics. features.ts split is mechanical refactoring.

**Scope**:
- estimator.ts: handle conditional edge branches (best=min, worst=max)
- Split features.ts into features/ directory with focused modules
- Move R1's rename code into features/rename.ts during split
- Update all imports in server.ts

**Files touched**:
- `src/analyzer/estimator.ts` — conditional edge branch handling
- `src/lsp/features.ts` → `src/lsp/features/` directory
- `src/lsp/server.ts` — import path updates

**Test target**: ~12 new tests
**Agent calls**: ~2

### R3: Hierarchical Document Symbols + Code Action Extraction (DIRECT)
