### R2: Multi-Hop Conditional Chain Estimation (MEDIUM)

**Justification for MEDIUM**: Design ambiguity — how to handle best/worst cost aggregation across multiple hops (additive? max? per-branch?). How to handle cycles in estimation (visited set? depth cap? both?). How to handle `done` targets mid-chain. The estimator has been single-hop since v3.4-R2; changing it touches cost semantics that affect budget reporting. R-PROC-14 applied: wait for A2+A3 analysis completion before convergence.

**Apply R-PROC-14**: Wait for A2+A3 analysis completion before convergence.
**Apply R-PROC-18**: Convergence spec must explicitly list error path tests (cycle estimation, depth limit estimation, empty chain estimation).

**Scope**:
- Update `getConditionalBranchCosts` in estimator.ts to walk conditional edge chains
- Follow `edgesBySource` chains, accumulate costs per hop
- Apply best=min / worst=max at each branch point (consistent with v3.4-R06 ratchet)
- Use visited set for cycle detection (consistent with runtime v3.7-R3 approach)
- Cap at MAX_CONDITIONAL_HOPS (import from flow-runner.ts or extract to constants.ts)
- Handle `done` as zero-cost terminal (consistent with v3.4-R06)

**Test target**: ~12 new tests (single-hop backward compat, 2-hop chain, 3+ hop chain, chain with cycle, chain to `done`, chain with fallback aliases, best/worst divergence across hops, depth limit, empty chain)
