# Graft v4.5 Design Spec -- Comparison Operators & Conditional Expressions

## Overview

v4.5 adds comparison operators to the expression system and introduces conditional (ternary) expressions. This completes the expression system for boolean logic in let bindings.

## Feature 1: Comparison Operators in Expressions

### Goal
Enable `<`, `>`, `<=`, `>=`, `==`, `!=` in Expr (currently only available in Condition for edge routing).

### Syntax
```graft
graph G(input: In, output: Out, budget: 10k) {
  A -> let valid = A.score > 50
     -> let exact = A.status == "ok"
     -> done
}
```

### Design

#### AST
Extend binary op union: `op: '+' | '-' | '/' | '*' | '%' | '<' | '>' | '<=' | '>=' | '==' | '!='`

#### Parser
Add `parseComparison` precedence level between `parseExpr` and `parseAdditive`:
```
parseExpr -> parseComparison (<, >, <=, >=, ==, !=) -> parseAdditive (+, -) -> parseMultiplicative (*, %, /) -> parseUnary (-, !) -> parsePrimary
```

#### Runtime (expr-eval.ts)
Handle comparison ops in binary case:
- `<`, `>`, `<=`, `>=`: numeric comparison via Number()
- `==`, `!=`: loose equality (matching existing Condition semantics)

#### Type Checker
- Comparison operators: result is always `boolean`
- `==`/`!=`: any types allowed
- `<`/`>`/`<=`/`>=`: warn if non-numeric operands

### Constraints
- Loose equality (`==`/`!=`) not strict, matching existing Condition semantics
- No chained comparisons: `a < b < c` is not supported (parsed as `(a < b) < c`)

## Feature 2: Conditional (Ternary) Expressions

### Goal
Support `if expr then expr else expr` syntax in expressions.

### Syntax
```graft
graph G(input: In, output: Out, budget: 10k) {
  A -> let label = if A.score > 50 then "high" else "low"
     -> let capped = if A.count > 100 then 100 else A.count
     -> done
}
```

### Design

#### AST
New Expr kind:
```typescript
| { kind: 'conditional'; condition: Expr; consequent: Expr; alternate: Expr; location: SourceLocation }
```

#### Parser
In parsePrimary (or as lowest-precedence level):
- When encountering `if` keyword in expression context, parse as conditional
- `if` <expr> `then` <expr> `else` <expr>
- Note: `then` and `else` need to be recognized as contextual keywords in expression parsing
- Actually, `else` is already a keyword (TokenType.Else). Need to add `Then` keyword.

#### Lexer/Tokens
- Add `Then` keyword token

#### Runtime (expr-eval.ts)
- Evaluate condition, return consequent if truthy, alternate if falsy

#### Type Checker
- Result type: union of consequent and alternate types
- If both are same type, result is that type; otherwise 'unknown'

### Constraints
- `else` branch is required (no bare `if-then`)
- Nesting supported: `if a then (if b then x else y) else z`
- `then` and `else` are contextual keywords in expressions only

## Scope Boundaries

**IN**: comparison operators, conditional expressions
**OUT**: logical operators (&&, ||), user-defined functions, pattern matching
