# Graft v3.1 — Design Spec: LSP Completions + API Surface + Bug Fixes

## 1. Goals

Polish and harden the v3.0 foundation. No new language syntax. Focus on developer experience (LSP completions), library usability (programmatic API), and fixing known bugs and tech debt identified in the v3.0 retrospective.

1. **LSP completion provider** — autocomplete for keywords, node names, context names, memory names, and field references in `.gft` files
2. **Programmatic API surface** — expose `compileToProgram`, `Executor`, `ProgramIndex` through package.json exports so library consumers don't need deep imports
3. **Parallel failure strategy bug fix** — parallel branches currently bypass `executeWithFailureStrategy`, silently ignoring `on_failure` (TD-04)
4. **Fallback cycle detection** — prevent `on_failure: fallback(self)` and mutual fallback loops (E-05)
5. **Tech debt cleanup** — eliminate duplicated state in Executor/ScopeChecker, extract shared CLI formatting, update stale error message (TD-01, TD-02, TD-03, TD-05)

## 4. Architecture Changes

### 4.1 LSP Completion Provider

Extends the existing LSP server (`src/lsp/server.ts` + `src/lsp/features.ts`). No new files needed.

**Completion contexts** (detected by cursor position analysis):

| Position | Completions offered | Source |
|----------|--------------------|----|
| Top-level (empty line) | `context`, `node`, `memory`, `graph`, `import`, `edge` | Keywords |
| Inside `reads: [` | Declared context names + memory names | ProgramIndex.contextMap, memoryMap |
| After `ContextName.` in reads | Fields of that context | ProgramIndex.producesFieldsMap |
| After `MemoryName.` in reads | Fields of that memory | ProgramIndex.memoryFieldsMap |
| Inside `writes: [` | Declared memory names | ProgramIndex.memoryMap |
| After `MemoryName.` in writes | Fields of that memory | ProgramIndex.memoryFieldsMap |
| Inside `graph { }` flow | Declared node names + `done` | ProgramIndex.nodeMap |
| After `->` in edge | Node names | ProgramIndex.nodeMap |
| After `from` in import | (No completions — file path) | N/A |
| After `import {` | Names exported by the resolved import | Cached program from import resolution |
| `model:` value position | Model aliases from MODEL_MAP keys | constants.ts |
| `on_failure:` value position | `retry(`, `fallback(`, `skip`, `abort` | Keywords |
| Inside `fallback(` | Node names | ProgramIndex.nodeMap |

**Registration**: `CompletionRequest` handler in server.ts, dispatch to `getCompletions()` in features.ts.

**Trigger characters**: `.` (field access), `[` (list open), `{` (brace open for multi-field).

### 4.2 Parallel Failure Strategy Fix

Current code in `flow-runner.ts:81-84`:
```typescript
// CURRENT (broken): raw executeNode bypasses failure strategies
await Promise.allSettled(targets.map(t => ctx.executeNode(t)));
```

Fix: wrap each parallel target in `executeWithFailureStrategy()`, respecting the node's `on_failure` declaration.

### 4.3 Fallback Cycle Detection

Add cycle detection in `ScopeChecker.checkFailureStrategies()`:
- Build a directed graph of fallback edges: `A -> B` when `A` has `on_failure: fallback(B)`
- Detect cycles via DFS with visited/in-stack sets (same pattern as import circular detection, v2.0-R14)
- New error code: `SCOPE_FALLBACK_CYCLE`

### 4.4 Programmatic API Surface

Current `package.json` exports:
```json
{
  ".": "./dist/index.js",
  "./ast": "./dist/parser/ast.js"
}
```

v3.1 additions:
```json
{
  ".": "./dist/index.js",
  "./ast": "./dist/parser/ast.js",
  "./compiler": "./dist/compiler.js",
  "./runtime": "./dist/runtime/executor.js",
  "./types": "./dist/types.js"
}
```

New `src/types.ts` barrel file re-exports public types:
- `Program`, `ProgramResult`, `CompileResult` from compiler
- `RunResult`, `TokenUsage` from runner/executor
- `ProgramIndex` from analyzer
- `GraftError`, `GraftErrorCode` from diagnostics
- `CodegenBackend`, `GeneratedFile` from codegen

This is the ONLY barrel file in the project (all other imports remain explicit per T1 ratchet). It exists solely as a public API boundary.

## 5. Error Code Changes

New code for v3.1:

```typescript
type ScopeErrorCode = ... | 'SCOPE_FALLBACK_CYCLE';
```

`SCOPE_FALLBACK_CYCLE`: emitted when fallback references form a cycle (A -> B -> A, or A -> A).

## 6. Breaking Changes

None. v3.1 is fully backward compatible:
- LSP completions are additive (new capability, no changed behavior)
- API exports are additive (new sub-paths, existing paths unchanged)
- Bug fixes change behavior only for previously-broken cases (parallel + failure strategies, fallback cycles)
- Tech debt cleanup is internal refactoring (no public API changes)

## 7. Ratchet Unlocks Required

None. All changes in v3.1 are additive or internal refactoring. No locked decisions need to be revisited.
