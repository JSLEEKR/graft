# Graft v3.9 Design Specification

**Date**: 2026-04-02
**Version**: 3.9.0
**Theme**: Quality polish + edge case closure (final v3.x release)

## Overview

v3.8 closed the last major parity gap (TD-03, estimator-runtime alignment for multi-hop conditional chains) and extracted the densest code block in the codebase (TD-02). The runtime is feature-complete. The estimator is aligned. The LSP is mature (8 features, unchanged for 2 versions). v3.9 is the final v3.x release -- it closes remaining edge case gaps, resolves the longest-carried tech debt (TD-01, 4 retros), and polishes the estimator's diagnostic codes. This positions v4.0 as a clean slate for the next feature wave.

## Features

### F-01: Edge Transforms on Conditional Edges (resolve SCOPE_TRANSFORM_CONDITIONAL)

- Currently, edge transforms declared on conditional edges are silently ignored at runtime. The scope checker emits `SCOPE_TRANSFORM_CONDITIONAL` as a warning, but the warning text implies transforms are unsupported rather than simply not yet implemented.
- Implement actual transform application on conditional edges in the runtime. When the runtime follows a conditional edge from A to B, any transforms declared on that edge (select, filter, drop, compact, truncate) are applied to the output before passing it to B.
- The existing edge transform infrastructure (pure TS functions in flow-runner.ts) is reusable -- the gap is in the conditional chain execution path, which bypasses the transform application step.
- After implementation, change `SCOPE_TRANSFORM_CONDITIONAL` from a warning to validated (remove the warning entirely, since transforms on conditional edges will be supported).
- Known since v3.3-R2; documented as a gap in every retro since.

### F-02: Estimator Diagnostic Code Specialization

- The estimator currently uses `BUDGET_EXCEEDED` for 3 distinct scenarios: actual budget exceeded, conditional chain cycle detected, and conditional chain depth limit exceeded.
- Add two new diagnostic codes: `BUDGET_CHAIN_CYCLE` and `BUDGET_CHAIN_DEPTH` to the `BudgetErrorCode` sub-union in `GraftErrorCode`.
- Update `getConditionalBranchCosts` in estimator.ts to use the new codes instead of overloading `BUDGET_EXCEEDED`.
- Update the `SCOPE_TRANSFORM_CONDITIONAL` removal (F-01 consequence): remove the warning code from `ScopeErrorCode` sub-union, update the scope checker to no longer emit it.
- Fallback cost inclusion in worst-case estimation: for `retry_then_fallback` strategies, worst-case should be `cost * (1 + maxRetries) + fallbackCost` instead of `cost * (1 + maxRetries)`. This is a known minor underestimate documented since v3.8.

### F-03: TD-01 Resolution (import-path regex to AST-based filtering)

- `collectRenameLocations` (rename.ts:133-138) uses a regex `from\s+"([^"]*)"` to detect import paths. False matches in import paths corrupt both rename and find-all-references (2 consumers).
- Replace with AST-based filtering: use ProgramIndex to check whether a match offset falls within an import path range. The import declaration's `path` field already has a `SourceLocation` with offset and length.
- ~15 lines of change. No behavioral change for correct inputs; eliminates false positives for edge cases where identifiers appear inside import path strings.
- Carried across 4 retros (v3.5, v3.6, v3.7, v3.8). R-PROC-19 (tech debt carry limit) mandates inclusion at 3+ retros.

## Non-Goals

- Memory importability (v2.0-R13 -- no user demand, defer to v4.0+)
- Token budget hard enforcement (v2.1-R15 -- advisory model sufficient, defer to v4.0+)
- New LSP features (LSP mature at 8 features, stable 2 versions)
- Async file I/O, source maps, workspace support (major features for v4.0+)
- Lexer error recovery (TD-05 -- marginal benefit for Graft file sizes)
- Second codegen backend (no user demand)
- Nested foreach annotation ordering (technically correct, rare scenario)
- TD-05 through TD-10 (all LOW -- carry forward with explicit justification per R-PROC-19)

## Ratchet Impact

- **Unlocks anticipated**: 0. No existing ratchets block F-01, F-02, or F-03.
- **v3.0-R26** (`SCOPE_TRANSFORM_CONDITIONAL` rename): remains valid as the code name, but the warning itself will be removed since F-01 makes transforms on conditional edges supported. The scope checker code path that emits this warning is deleted, not renamed.
- **v3.4-R06** (conditional edge estimation: best=min, worst=max): remains valid. F-02 adds fallback cost but does not change the per-branch-point logic.
- **v2.2-R08** (GraftErrorCode union): will gain 2 new members (`BUDGET_CHAIN_CYCLE`, `BUDGET_CHAIN_DEPTH`) and lose 1 (`SCOPE_TRANSFORM_CONDITIONAL`). Net +1 member. No unlock needed -- the union type is extensible by design.
