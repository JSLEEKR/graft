# Graft v4.8 Design Spec — LSP Expression Intelligence

## Overview

v4.8 adds expression-aware LSP features: hover docs for variables (showing inferred types), go-to-definition for variables, and completions inside expression contexts. This brings the IDE experience up to par with the expression system built in v4.0-v4.7.

## Feature 1: Variable Hover (Inferred Type)

### Goal
When hovering over a variable name (from `let`) in a flow, show its inferred type and the expression it was bound to.

### Example
```
let score = A.result + 10
    ^--- hover: "let score: number = A.result + 10"
```

### Design
- In hover handler, check if word matches a `let` binding name
- Walk the graph's flow to find the `let` node
- Use TypeChecker's `inferExprType` to determine the type
- Format: `let {name}: {type} = {expression source}`

## Feature 2: Variable Go-to-Definition

### Goal
When using go-to-definition on a variable reference, jump to its `let` declaration.

### Design
- In definition handler, check if word matches a `let` binding
- Return the location of the `let` FlowNode

## Feature 3: Expression Context Completions

### Goal
Inside an expression (after `let x =`), provide context-aware completions:
- Node names (for field access like `A.score`)
- Variable names (from prior `let` bindings)
- Builtin function names
- Keywords: `if`, `then`, `else`

### Design
- Detect expression context: after `=` in a `let` binding line
- Provide completions for available identifiers

## Scope Boundaries

**IN**: variable hover, variable go-to-def, expression completions
**OUT**: expression-level diagnostics in LSP, inline type hints, code actions
