# Graft v3.8 Design Specification

**Date**: 2026-04-02
**Version**: 3.8.0
**Theme**: Estimator-runtime parity + flow-runner extraction + runtime polish

## Overview

v3.7 closed the runtime's multi-hop conditional routing gap. v3.8 closes the estimator's matching gap (TD-03, carried forward across 5 retros) and extracts the densest code block in the codebase (TD-02, 66-line case block at 3 nesting levels). A third round adds foreach iteration context to error messages (deferred from v3.7-R2). A final integration round covers cross-feature interactions.

## Features

### F-01: Flow-Runner Extraction (TD-02 + TD-04)

- Extract `executeConditionalChain()` from the `case 'node'` block in flow-runner.ts (lines 100-153, 53 lines of multi-hop routing logic)
- Extract `applyFallbackAlias()` helper to deduplicate the fallback alias pattern at 2 sites (TD-04, lines 96-98 and 140-142)
- The `case 'node'` block should drop from 66 lines to ~15-20 lines
- Pure extraction refactoring — no behavioral changes, all existing tests must continue passing

### F-02: Multi-Hop Conditional Chain Estimation (TD-03)

- Update `getConditionalBranchCosts` in estimator.ts to follow conditional edge chains the same way the runtime does
- Walk `edgesBySource` chains, accumulate costs per hop, apply best/worst at each branch point
- Use a visited set to handle cycles (matching runtime's approach), cap at MAX_CONDITIONAL_HOPS
- Current behavior: estimates cost for first hop only (one branch point)
- Target behavior: estimates cost for all hops in a chain (A->B->C->D estimates B+C+D)
- Closes the estimator-runtime parity gap that has been carried since v3.3 and promoted to MEDIUM priority in v3.7 retro

### F-03: Foreach Iteration Context in Error Messages

- When a foreach body node fails, include the iteration index in the error message
- Current: "Node X failed" — no indication of which iteration
- Target: "Node X failed (foreach iteration 3 of 5)" or equivalent
- Deferred explicitly from v3.7-R2 convergence
- Does not change error handling behavior — only enriches the error message string

## Non-Goals

- Memory importability (v2.0-R13 — no user demand)
- Edge transforms on conditional edges (SCOPE_TRANSFORM_CONDITIONAL — separate concern)
- Token budget hard enforcement (v2.1-R15 — deferred)
- New LSP features (LSP mature at 8 features)
- Async file I/O, source maps, workspace support
- Parallel + multi-hop conditional interaction testing at scale (future version)

## Ratchet Impact

- **Unlocks anticipated**: 0. No existing ratchets block any F-01/F-02/F-03 work.
- **v3.4-R06** (conditional edge estimation: best=min, worst=max) remains valid — F-02 extends it to multi-hop but does not contradict it. The per-branch-point logic (min/max) stays the same; it is applied at each hop.
