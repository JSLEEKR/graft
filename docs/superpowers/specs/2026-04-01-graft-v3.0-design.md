# Graft v3.0 — Design Spec: Multi-Backend + Field-Level Writes + Multi-Field Partial Reads

## 1. Goals

Transform Graft from a Claude-only compiler into a multi-backend system, and add precise field-level data routing for both reads and writes. This is the largest architectural change since v1.0, touching every pipeline stage.

1. **Multi-backend codegen** — abstract code generation behind a `CodegenBackend` interface so Graft programs can target Claude Code (default), OpenAI Agents, or future backends
2. **Field-level writes** — `writes: [Memory.field1, Memory.field2]` syntax for compile-time validation of which memory fields a node modifies
3. **Multi-field partial reads** — `reads: [Context.{field1, field2}]` syntax to select multiple fields from a single context, improving token budget optimization
4. **Compiler pipeline split** — decompose `compile()` into `compileToProgram()` + `compileAndGenerate()` for LSP optimization and incremental compilation
5. **Failure strategies** — `on_failure: retry(3) | fallback(NodeName) | skip` per node, replacing the current abort-on-failure MVP

## 4. Syntax Changes

### 4.1 Field-level writes

Current:
```
node Summarizer {
  model: sonnet
  reads: [Article]
  writes: [KnowledgeBase]
}
```

v3.0:
```
node Summarizer {
  model: sonnet
  reads: [Article]
  writes: [KnowledgeBase.summary, KnowledgeBase.keywords]
}
```

- `writes` clause accepts dotted field references: `MemoryName.fieldName`
- Whole-memory writes (`writes: [KnowledgeBase]`) remain valid for backward compatibility
- When field-level writes are used, `saveMemory` only merges the declared fields
- ScopeChecker validates that each field exists in the memory's schema
- TypeChecker checks per-field overlap when two nodes write to the same memory fields

AST representation:
```typescript
interface WriteRef {
  memory: string;          // "KnowledgeBase"
  field?: string;          // "summary" — undefined means whole-memory write
  location: SourceLocation;
}
// NodeDecl.writes: WriteRef[]  (replaces string[])
```

### 4.2 Multi-field partial reads

Current:
```
node Analyzer {
  model: sonnet
  reads: [Context.question]
}
```

v3.0:
```
node Analyzer {
  model: sonnet
  reads: [Context.{question, background}]
}
```

- Brace syntax `Context.{field1, field2}` selects multiple fields from one context
- Single-field syntax `Context.field` remains valid (sugar for `Context.{field}`)
- Whole-context syntax `Context` remains valid
- Token estimation: `PARTIAL_FIELD_FACTOR * fieldCount` (currently `PARTIAL_FIELD_FACTOR * 1`)

AST representation:
```typescript
interface ContextRef {
  context: string;           // "Context"
  field?: string[];          // ["question", "background"] — replaces string | undefined
  location: SourceLocation;
}
```

### 4.3 Failure strategies

Current: no syntax (abort-on-failure is hardcoded in flow-runner.ts)

v3.0:
```
node Risky {
  model: opus
  on_failure: retry(3)
  reads: [Input]
  produces: Output { ... }
}

node Fallback {
  model: haiku
  on_failure: skip
  reads: [Input]
  produces: Output { ... }
}

node Primary {
  model: opus
  on_failure: fallback(Fallback)
  reads: [Input]
  produces: Output { ... }
}
```

- `on_failure` clause in node declaration (optional, defaults to `abort`)
- Three strategies: `retry(N)`, `fallback(NodeName)`, `skip`
- `retry(N)`: re-execute the node up to N times on failure
- `fallback(NodeName)`: on failure, execute the named node instead
- `skip`: silently skip the node's output on failure (downstream nodes see null)
- ScopeChecker validates fallback node references exist
- Error codes: `RUNTIME_RETRY_EXHAUSTED`, `RUNTIME_FALLBACK_FAILED`, `RUNTIME_SKIPPED`

### 4.4 Backend selection

Current: hardcoded Claude Code output

v3.0:
```bash
# CLI
graft compile app.gft                    # default: claude
graft compile app.gft --backend claude
graft run app.gft --backend claude
```

Programmatic:
```typescript
import { compileAndGenerate } from '@graft-lang/graft';

const result = compileAndGenerate(source, filePath, { backend: 'claude' });
```

The `CodegenBackend` interface:
```typescript
interface GeneratedFile {
  path: string;
  content: string;
}

interface CodegenBackend {
  name: string;
  generateAgent(node: NodeDecl, index: ProgramIndex): GeneratedFile;
  generateHook(edge: EdgeDecl): GeneratedFile | null;
  generateOrchestration(program: Program, report: TokenReport, index: ProgramIndex): GeneratedFile;
  generateSettings(program: Program, index: ProgramIndex): GeneratedFile;
}
```

v3.0 ships with `ClaudeCodeBackend` only. The interface enables v3.1+ to add OpenAI, local LLM, etc.

## 5. Pipeline Architecture

### 5.1 compile() split

Current:
```
compile(source, filePath) → CompileResult
  lex → parse → resolve → scope → type → estimate → generate
```

v3.0:
```
compileToProgram(source, filePath) → ProgramResult
  lex → parse → resolve → scope → type → estimate
  Returns: { program, index, diagnostics, warnings, report }

compileAndGenerate(source, filePath, options?) → CompileResult
  compileToProgram() → generate(backend)
  Returns: { ...ProgramResult, files, outputDir }
```

- `compileToProgram()` is the LSP entry point (no codegen side effects)
- `compileAndGenerate()` is the CLI entry point (includes file generation)
- Both share the same lex-parse-resolve-analyze pipeline
- ProgramIndex constructed once in `compileToProgram()`, threaded to all stages

### 5.2 ProgramIndex extensions

Current maps: `contextMap`, `nodeMap`, `memoryMap`, `edgesBySource`, `producesNodeMap`

v3.0 additions:
- `graphMap: Map<string, GraphDecl>` — for multi-graph support (RD-10)
- `producesFieldsMap: Map<string, Map<string, TypeExpr>>` — fields per produces type (TD-02)
- `memoryFieldsMap: Map<string, Map<string, TypeExpr>>` — fields per memory type (TD-02)

These field-level maps are needed by:
- ScopeChecker (validate field-level writes)
- TypeChecker (per-field overlap checks)
- TokenEstimator (multi-field partial read estimation)
- LSP (hover info for field references)

### 5.3 RuntimeState extraction

```typescript
interface RuntimeState {
  outputs: Map<string, unknown>;
  input: Record<string, unknown>;
}

interface PromptContext extends RuntimeState {
  memories: Map<string, unknown>;
  program: Program;
  index: ProgramIndex;
}

interface FlowContext extends RuntimeState {
  executeNode: (name: string, options?: NodeExecutionOptions) => Promise<NodeResult>;
  onFailure: FailureStrategy;  // per-graph default
}

interface NodeExecutionOptions {
  retryCount?: number;
  isFallback?: boolean;
}
```

## 7. Error Code Expansion

New codes for v3.0:

```
SCOPE_TRANSFORM_CONDITIONAL    (rename from TRANSFORM_ON_CONDITIONAL)
SCOPE_INVALID_WRITE_FIELD      (field-level writes: field not in memory schema)
SCOPE_INVALID_FALLBACK         (fallback node reference does not exist)
TYPE_WRITE_FIELD_OVERLAP       (two nodes write same field of same memory)
RUNTIME_RETRY_EXHAUSTED        (retry(N) exhausted all attempts)
RUNTIME_FALLBACK_FAILED        (fallback node also failed)
RUNTIME_SKIPPED                (node skipped via on_failure: skip)
PARSE_UNEXPECTED_TOKEN         (structured parse error for LSP)
PARSE_MISSING_FIELD            (structured parse error for LSP)
CONFIG_UNKNOWN_BACKEND         (--backend flag not recognized)
```

Organized as sub-unions per RD-16 recommendation:
```typescript
type ScopeErrorCode = 'SCOPE_DUPLICATE_NAME' | 'SCOPE_UNDEFINED_REF' | ... | 'SCOPE_TRANSFORM_CONDITIONAL' | 'SCOPE_INVALID_WRITE_FIELD' | 'SCOPE_INVALID_FALLBACK';
type RuntimeErrorCode = 'RUNTIME_RETRY_EXHAUSTED' | 'RUNTIME_FALLBACK_FAILED' | 'RUNTIME_SKIPPED';
type ParseErrorCode = 'PARSE_UNEXPECTED_TOKEN' | 'PARSE_MISSING_FIELD';
type ConfigErrorCode = 'CONFIG_UNKNOWN_BACKEND';
type GraftErrorCode = ScopeErrorCode | TypeErrorCode | BudgetErrorCode | ImportErrorCode | GraphErrorCode | RuntimeErrorCode | ParseErrorCode | ConfigErrorCode;
```

## 8. Breaking Changes

1. **`ContextRef.field`**: `string | undefined` becomes `string[] | undefined`. All consumers of `ContextRef.field` must handle arrays.
2. **`NodeDecl.writes`**: `string[]` becomes `WriteRef[]`. All consumers of `NodeDecl.writes` must handle the new type.
3. **`compile()` renamed to `compileAndGenerate()`**. A new `compileToProgram()` function is added. The old `compile()` is kept as a deprecated alias for one version.
4. **`TRANSFORM_ON_CONDITIONAL`** renamed to `SCOPE_TRANSFORM_CONDITIONAL`.
5. **`GraftErrorCode` union** reorganized into sub-unions (runtime type unchanged, authoring ergonomics improved).

Backward compatibility notes:
- Existing `.gft` files with `writes: [MemoryName]` (no dot) continue to work (whole-memory write)
- Existing `.gft` files with `reads: [Context.field]` (single field) continue to work
- Existing `.gft` files without `on_failure` continue to work (defaults to abort)
- The `compile()` function is kept as a deprecated alias
