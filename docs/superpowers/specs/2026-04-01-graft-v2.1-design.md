# Graft v2.1 — Design Spec: Real-Time Token Tracking

## 1. Goals

Add runtime token tracking to the Graft execution engine. Currently, token budgets are estimated at compile time but never measured at runtime. v2.1 closes this gap:

1. **Token usage capture** — parse actual token counts from Claude CLI output per node
2. **Runtime budget enforcement** — warn/halt when cumulative usage approaches graph budget
3. **Token log writing** — populate `.graft/token_log.txt` with per-node actuals (currently scaffolded but empty)
4. **Post-run comparison** — extend `TokenReport` with actuals for estimate-vs-actual calibration

Additionally, v2.1 addresses correctness gaps and tech debt identified in the v2.0 retrospective.

## 4. Technical Design

### 4.1 Shared Constants and Utilities

**New file: `src/constants.ts`**

```typescript
/** Model name aliases to full Claude model identifiers. */
export const MODEL_MAP: Record<string, string> = {
  sonnet: 'claude-sonnet-4-20250514',
  opus: 'claude-opus-4-20250514',
  haiku: 'claude-haiku-4-5-20251001',
};

/** Fraction of a context/memory's maxTokens used when reading a single field. */
export const PARTIAL_FIELD_FACTOR = 0.3;

/** Budget threshold fractions for runtime enforcement. */
export const BUDGET_WARNING_THRESHOLD = 0.8;
export const BUDGET_CRITICAL_THRESHOLD = 0.9;
```

**New file: `src/utils.ts`**

Extract `fieldsToJsonExample` and `typeToExample` here. Both `agents.ts` and `executor.ts` import from utils instead of duplicating.

```typescript
import { Field, TypeExpr } from './parser/ast.js';

export function fieldsToJsonExample(fields: Field[]): Record<string, unknown> { ... }
function typeToExample(type: TypeExpr): unknown { ... }
```

**Migration**: `agents.ts`, `settings.ts`, and `executor.ts` all import `MODEL_MAP` from `constants.ts`. `agents.ts` and `executor.ts` import `fieldsToJsonExample` from `utils.ts`. Existing ratchets (T6, v1.2-R06) are superseded by the extraction.

### 4.2 Memory Manager Extraction

**New file: `src/runtime/memory.ts`**

Extract from `executor.ts`:
- `loadMemory(name, memoryDir, program): Record<string, unknown> | null`
- `saveMemory(name, nodeOutput, memoryDir, program, dryRun): void`

The `Executor` class delegates to these functions. This keeps executor.ts focused on orchestration and creates a clear module boundary for memory I/O.

```typescript
import { Program } from '../parser/ast.js';

export function loadMemory(

export function saveMemory(
  name: string,
  nodeOutput: unknown,
  memoryDir: string,
  program: Program,
  dryRun: boolean,

```

### 4.3 Correctness: Writes Schema Validation (RT-03)

In `TypeChecker`, add a check: for each node that writes to a memory, verify that at least one `produces` field name overlaps with the target memory's field names. A writes clause with zero field overlap is almost certainly a bug.

```
For each node N with writes: [M]:
  producesFieldNames = set(N.produces.fields.map(f => f.name))
  memoryFieldNames = set(M.fields.map(f => f.name))
  if intersection(producesFieldNames, memoryFieldNames) is empty:
    error("Node 'N' writes to memory 'M' but produces no matching fields")
```

This is a warning-level diagnostic, not an error, since the field-matching merge in `saveMemory` would silently write nothing.

### 4.4 Correctness: max_tokens > 0 Validation (RT-04)

In `TypeChecker` or `ScopeChecker`, add validation:
- For each `MemoryDecl`: `maxTokens > 0` or error
- For each `ContextDecl`: `maxTokens > 0` or error

Per ratchet v2.0-R10, this is analyzer responsibility, not parser.

### 4.5 Correctness: Parallel Memory Write Detection (RT-05)

In `ScopeChecker`, when checking graph flow:
- For each `parallel` FlowNode, collect all `writes` from all branch nodes
- If two branches write the same memory name, emit a warning: "Nodes 'A' and 'B' both write to memory 'M' in parallel; last-write-wins is nondeterministic"

This is a warning, not an error, since the behavior is defined (last-write-wins) but likely unintentional.

### 4.6 TokenUsage Interface (RT-07)

**Extend `SpawnResult` in `subprocess.ts`:**

```typescript
export interface TokenUsage {
  inputTokens: number;
  outputTokens: number;
}

export interface SpawnResult {
  stdout: string;
  stderr: string;
  exitCode: number | null;
  tokenUsage?: TokenUsage;  // NEW: parsed from Claude CLI output
}
```

**Parsing strategy**: Claude CLI with `--output-format json` emits a JSON object containing `usage` with `input_tokens` and `output_tokens`. However, Graft currently uses `--print` mode which outputs raw text. Two approaches:

1. **Switch to `--output-format json`**: get structured output including token usage. Requires changing `extractJson` to unwrap the result field.
2. **Parse stderr**: Claude CLI may emit usage info to stderr. Less reliable.

**Decision**: Switch to `--output-format json` for nodes. The response includes:
```json
{
  "result": "...",
  "usage": { "input_tokens": 1234, "output_tokens": 567 }
}
```

Update `spawnClaude` to parse this structure when `--output-format json` is used. The `extractJson` function extracts the `result` field for downstream processing. `tokenUsage` is populated from the `usage` field.

If the CLI output does not contain parseable usage data (e.g., older CLI versions, non-JSON mode), `tokenUsage` remains `undefined` and the system gracefully degrades to estimate-only mode.

### 4.7 Runtime Budget Tracking (RT-09)

Add a `TokenTracker` class to the executor (or as a standalone utility):

```typescript
export class TokenTracker {
  private budget: number;
  private consumed: number = 0;
  private entries: TokenLogEntry[] = [];

  constructor(budget: number) {
    this.budget = budget;
  }

  record(nodeName: string, usage: TokenUsage | undefined, estimated: { in: number; out: number }): void {
    const actual = usage ? usage.inputTokens + usage.outputTokens : undefined;
    const est = estimated.in + estimated.out;
    this.consumed += actual ?? est;
    this.entries.push({ nodeName, actual, estimated: est, cumulative: this.consumed, timestamp: new Date().toISOString() });
  }

  get fraction(): number { return this.budget > 0 ? this.consumed / this.budget : 0; }
  get isWarning(): boolean { return this.fraction >= BUDGET_WARNING_THRESHOLD; }
  get isCritical(): boolean { return this.fraction >= BUDGET_CRITICAL_THRESHOLD; }

  getEntries(): TokenLogEntry[] { return [...this.entries]; }
}

interface TokenLogEntry {
  nodeName: string;
  actual: number | undefined;
  estimated: number;
  cumulative: number;
  timestamp: string;
}
```

**Budget enforcement in executor**:
- After each node execution, call `tracker.record(...)`.
- If `tracker.isWarning`, log to verbose output: `[BUDGET] 80% consumed — consider compact mode`.
- If `tracker.isCritical`, log: `[BUDGET] 90% consumed — skipping non-critical nodes recommended`.
- Budget enforcement is advisory (log + field in RunResult), not a hard abort. The orchestrator/caller decides whether to stop.

**RunResult extension**:
```typescript
export interface RunResult {
  // ... existing fields ...
  tokenUsage?: {              // NEW
    budget: number;
    consumed: number;
    fraction: number;
    perNode: Array<{
      node: string;
      actual?: number;
      estimated: number;
    }>;
  };
}
```

### 4.8 Token Log Writing (RT-08, RD-06)

After each node execution, append a line to `.graft/token_log.txt`:

```
[2026-04-01 14:30:00] Node Responder | estimated: 6000 | actual: 5230 | cumulative: 5230/16000 (33%)
[2026-04-01 14:30:05] Node Summarizer | estimated: 3000 | actual: 2810 | cumulative: 8040/16000 (50%)
```

Format: `[timestamp] Node <name> | estimated: <est> | actual: <actual|N/A> | cumulative: <cum>/<budget> (<pct>%)`

This replaces the current empty scaffold with real data. The hook-generated bash scripts continue to write edge transform byte-level stats to the same file, creating a unified log.

**Implementation**: The `TokenTracker.record()` method also writes to the log file (path passed at construction). File is opened in append mode (`fs.appendFileSync`).

### 4.9 TokenReport Actuals Extension (RD-07)

Extend the estimator's `NodeTokenReport` with optional actual fields, populated after a run:

```typescript
export interface NodeTokenReport {
  name: string;
  estimatedIn: number;
  estimatedOut: number;
  actualIn?: number;    // NEW: populated after run
  actualOut?: number;   // NEW: populated after run
}

export interface TokenReport {
  // ... existing fields ...
  actualTotal?: number;  // NEW: sum of all actuals, populated after run
}
```

The `RunResult.tokenUsage.perNode` data feeds back into the `TokenReport` for post-run comparison. This enables calibration: if estimates consistently over/under-predict, the partial factor and transform reduction estimates can be tuned.

## 6. Non-Goals (deferred)

- Dollar-cost tracking (token-to-USD conversion)
- Automatic budget adjustment (auto-resize budgets based on actuals)
- Memory importability across files
- Double-parse elimination in compiler.ts
- SQLite/Redis memory storage backends
- Token streaming (real-time partial usage updates during node execution)
- Hard budget abort (executor stops mid-pipeline) — advisory only in v2.1
