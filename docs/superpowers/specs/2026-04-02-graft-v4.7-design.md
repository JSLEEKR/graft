# Graft v4.7 Design Spec — Null Coalescing & Expression Hardening

## Overview

v4.7 adds the null coalescing operator (`??`) for safe default values and hardens the expression system with better runtime error messages and edge case handling. This is the final v4.x expression feature release.

## Feature 1: Null Coalescing Operator (`??`)

### Goal
Enable `??` for providing default values when a field or expression is null/undefined.

### Syntax
```graft
graph G(input: In, output: Out, budget: 10k) {
  A -> let name = A.optional_name ?? "anonymous"
     -> let count = A.item_count ?? 0
     -> done
}
```

### Design

#### Lexer/Tokens
- Add `QuestionQuestion` token (`??`)

#### AST
Extend binary op union: add `'??'`

#### Parser Precedence
`??` sits at the same level as logical OR (lowest after assignment):
```
parseExpr → parseLogicalOr (||) → parseLogicalAnd (&&) → parseComparison → parseAdditive → parseMultiplicative → parseUnary → parsePrimary
```
Actually, `??` should be at its own level between `||` and `&&` to avoid ambiguity with logical operators.

Revised:
```
parseExpr → parseNullCoalesce (??) → parseLogicalOr (||) → parseLogicalAnd (&&) → parseComparison → ...
```

#### Runtime (expr-eval.ts)
- `??`: if left is null or undefined, return right; otherwise return left
- NOT the same as `||` — `0`, `false`, `""` are NOT nullish

#### Type Checker
- Result type: union of left and right types (same as conditional)
- No special warnings needed

### Constraints
- `??` checks for null/undefined only (not falsy)
- Cannot be mixed with `||` or `&&` without parentheses in most languages, but we'll allow it for simplicity
- `?` alone is not an operator (no ternary `? :` syntax)

## Feature 2: Runtime Expression Error Hardening

### Goal
Improve runtime expression evaluation with better error handling and warning messages.

### Changes
- Field access on undefined source: warn instead of silently returning undefined
- Division by zero already warns — ensure consistency across all ops
- Template interpolation with undefined: produce "[undefined]" instead of "undefined"

## Scope Boundaries

**IN**: null coalescing (??), runtime error hardening
**OUT**: optional chaining (?.), array/object literals, pattern matching, user-defined functions
