# Graft v4.1 Design Spec — Quality & Expression Hardening

## Version Goal

Fix the only MEDIUM tech debt (conditionFieldName multi-segment), harden expression evaluation, and extract the growing scope checker. No new user-facing features — this is a quality release.

## Scope

### IN

1. **conditionFieldName multi-segment fix (TD-NEW-01)**: `evaluateCondition` multi-segment LHS produces dotted key for flat lookup — always misses. Fix by evaluating multi-segment Condition.left through `evaluateExpr` path instead of `output[conditionFieldName()]`.

2. **Graph call output isolation (TD-NEW-05)**: Child graph shares parent outputs map. Child node output silently overwrites same-named parent node output. Fix by giving child a scoped outputs map and merging results.

3. **Scope checker extraction**: scope.ts at 694 lines. Extract graph-related checking (recursion, call args, variable collision, expr sources) to `src/analyzer/graph-checker.ts`.

4. **Exhaustive FlowNode switch (P-03)**: Add TypeScript `never` default to all 3 FlowNode walkers (scope.ts, types.ts, flow-runner.ts) so new kinds cause compile-time errors.

5. **Division by zero warning (TD-NEW-03)**: Emit runtime warning instead of silent 0 return.

### OUT

- New operators (`*`, `%`) — no demand, flat precedence intentional
- Variable mutation/reassignment — `let` is immutable binding
- Memory importability (v2.0-R13) — no demand
- Nested parallel-in-foreach (v4.0-R09) — no use cases yet

## Technical Notes

### conditionFieldName fix
The bridge function `conditionFieldName()` was designed for backward compat during the Condition.left migration. Now that migration is complete, the `evaluateCondition` function should call `evaluateExpr(condition.left, outputs, variables)` directly for all LHS evaluation, bypassing `conditionFieldName` entirely. The bridge function can be deprecated.

### Output isolation
Child FlowContext should receive `outputs: new Map(ctx.outputs)` (shallow clone) instead of sharing via spread. After child execution, parent can read results through an explicit merge step or through the child's returned NodeResults.

### Scope extraction
The new `graph-checker.ts` takes `checkGraphRecursion`, `collectGraphCalls`, `dfsGraphCycles`, `checkGraphCallArgs`, `checkVarCollision`, `checkExprSources`, and the module-level `checkLiteralParamType`. ScopeChecker delegates to it.
